# 待核实文档的 Agent 处理建议

入口：**知识库 → 知识维护 → 待核实 → 生成处理建议**。

检查规则先说明为什么出现提醒；处理建议再结合当前原文、文档类型和已检索到的相关文档，回答具体应该处理什么、有哪些依据，以及哪些信息仍需人来确认。

## 按类型提出建议

| 问题 | 建议重点 |
| --- | --- |
| 缺少文档关联、缺少正式关联 | 从已有文档中寻找相关主题，说明关联理由；独立笔记不必为了消除提醒强行建立链接。 |
| 链接目标未找到 | 核对失效位置与真实候选目标，区分路径变化和资料缺失；无法确定目标时列出需要补充的信息。 |
| 标题重复 | 比较同名文档的用途和范围，建议明确标题、保留差异或进一步比较。标题相同不等于内容重复。 |
| 缺少类型要点、内容可能待完善 | 结合文档类型指出缺失信息，给出整理步骤或补充草稿。设计文档关注目标、决策和风险，报告关注有依据的结果；不补造实验或验证结论。 |
| 设计缺少计划、变更状态待更新、任务产物缺失 | 列出应核对的计划、进度和产物，再给出维护步骤。文件不存在不等于任务没有执行。 |
| 结论依据待核实、证据需要更新 | 区分当前记录与可核对依据，列出待确认的问题；没有充分证据时不代替用户确认结论。 |
| 图表语法问题 | 针对原文中的图表和报错提出修正方向，不声称已经运行渲染或验证。 |

## 使用方式

选择提醒时只读取仍然有效的已保存建议。用户点击生成后，使用设置中的辅助模型生成中文建议，不创建 OMP 会话，也不自动逐篇调用模型。可以重新生成；请求失败时显示原因并允许重试。

建议包含具体判断、处理步骤、可选补充草稿、待确认事项和原文依据。依据可以打开对应文档核对。原文和提醒的处理状态仍由现有操作控制，生成建议本身不编辑文档、不忽略提醒、不确认事实。

对于已不需要保留的文档，可使用同一详情页的 **删除文档**。确认框展示文档名、来源和路径；确认后移出知识目录，并清除这篇文档的所有核实提醒。当前正文转入本地删除记录，历史版本保留；不会删除导入前的源文件、附件或其他关联文档。其他文档中指向它的链接可能失效。

删除绑定当前检查版本；文档或检查依据发生变化时会拒绝旧确认，需刷新后重新核对。重复请求使用同一个操作编号，避免再次处理同路径的新文档。索引更新失败时明确提示“已删除、索引待更新”。本地删除不传播到远端同步仓库，也不会被旧同步记录或后台任务自动恢复。本轮不提供批量删除和回收站界面。

## 上下文与版本

服务端重新定位提醒并核对其检查版本，再读取当前文档和相关候选。模型只能引用本次实际提供的文档和其中可核对的原文；检索结果是候选材料，不能仅凭主题相似就认定为正确依据。长文摘录、资料不可读或检索不完整会在建议中体现其限制。

建议保存在本地知识服务中，绑定提醒、目标文档与所用上下文版本。原文或关联材料变化后不继续复用旧建议；生成期间发生变化时也不发布过期结果。页面切换到另一条提醒时不显示上一个请求的结果。

未配置辅助模型时，界面提示配置后重试。新增能力需要新的 Lucyna 主进程和知识服务加载；正在运行的旧知识服务会提示先完成现有任务，再重启知识服务。
