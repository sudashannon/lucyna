# 默认知识沉淀任务

每个有效、已登记的本地 WSL Work 默认开启一项独立任务：由内嵌 `AuxiliaryAgent` 从 L1 笔记和 L2 日志提炼可复用知识，自动保存到内置知识库的 **Work 经验 · L3**。不创建 OMP session，不依赖自动命名开关，不需要配置 RSI 评测。普通任务和 RSI 原有的公共 L3/skill 只读限制保持不变；RSI 候选仍由用户采纳。

入口：**工作 → 后台任务 → 知识沉淀 · L1 / L2 → L3**。可查看状态、已知 Token 用量、来源数量、历史记录、跳过原因以及排版后的入库结果；支持暂停、恢复和重新检查资料。入库文档也可在知识库中检索、阅读和编辑。

## 调度与生命周期

- 主进程每 30 秒向已有私有知识服务同步有效 Work、会话忙闲及辅助模型配置。仅信任主进程的 Work 清单，renderer 不能指定文件目录或模型凭据。
- 知识服务每 10 秒调度，全局串行执行。Work 和资料稳定 60 秒后触发；每个 Work 两次任务至少间隔 30 分钟，每次最多处理 3 份变化资料，积压资料后续继续处理。
- 来源内容 SHA-256 未变化时不重复请求模型。暂停状态和处理进度持久保存，重新同步不会重新开启用户暂停的任务。移出 Work 清单后停止调度。
- 使用现有辅助模型接口，不设 Token 总量或输出 Token 上限；单份资料的模型调用有 10 分钟超时。显示成功返回请求的已知用量，不将中断请求假装为完整账单。
- 服务独立于窗口，存在启用任务时保持运行，正常关闭客户端后继续。系统重启不保证自动启动；服务重新启动后要等客户端同步模型配置，凭据只在内存中保存。
- 旧知识服务不被强制重启。若不支持此功能，界面提示等待下次服务启动，并避免轮询阻止旧服务正常空闲退出。

## 输入与输出

输入只包括 `notes/` 下的 Markdown（最多 5 层）和根目录 `SESSION-*.md`。不读取 L0 `SESSION.md`、仓库源码、脚本、隐藏目录和符号链接。最多扫描 2000 个目录项，单文件最多 120 KB，超出或含疑似凭据的资料显示跳过原因，原件保留；较大的日志应拆分。

每份资料最多提炼 12 条结论，每条必须包含标题、知识、适用范围和 8–1600 字符的连续原文摘录。宿主检查摘录确实存在且输出不含已识别凭据。模型没有文件写入、命令、网络浏览或库写入工具；发布由宿主完成。文档正文不是授权，不允许借文档指令扩大范围。

每个 Work 对应一个稳定的汇总文档。重新提炼某份来源会替换该来源的旧贡献，保留其他来源；完全相同的标题、结论和适用范围合并出处。已有条目提供给模型以帮助复用措辞，但**不保证语义相近的所有条目都自动合并**。原文摘录检查不等于事实核验，入库文档明确保留适用范围和来源版本，不宣称额外运行过测试。

入库前重新读取来源，变化则丢弃本轮提炼结果。来源删除或暂不可读时保留既有历史知识，不自动删除；每条出处含提炼时间与源文件哈希。

## 持久写入与故障恢复

在 `catalog.sqlite` 的独立调度表中保存政策、来源指纹、提炼结果、最近 20 条记录和待发布内容，不保存模型密钥。沿用 `KnowledgeLibrary` 的乐观版本检查、不可变修订和幂等 operationId；写入成功但索引失败时，重试同一待发布内容，不重复创建修订或调用模型。

人工修改已有汇总文档后，自动任务不会覆盖它，会提示冲突并保留待发布内容；用户可在知识库核对与合并。暂停停止在途提炼和后续请求；已经提交的写入完成持久化核对后保留，不回滚用户可见知识。生成格式/出处失败时，不入库；同一失败来源自动等待变更或用户点击重新检查，避免反复消耗模型请求。
