# 重复与冲突检查（第二阶段第一批）

入口：**知识库 → 知识维护 → 重复与冲突**。

本批实现自动发现、两侧证据对照、整理建议、单独模型复核和人工处理记录。**确认只登记判断与整理方向，不合并、拆分、删除、改类或迁移原文。** 跨文档批量写入、引用迁移和整批回退属于后续批次。

## 判断与建议

| 类型 | 判定条件 | 建议方向 |
| --- | --- | --- |
| 疑似重复 | 原文表达同一结论，且明确适用范围一致 | 准备公共步骤的合并方向，列出独有内容、来源及限定条件的保留要求 |
| 同范围冲突 | 相同设备、版本、环境和时间条件下，结论不能同时成立 | 列出需要补充的原始日志、证据与核查步骤；不因文档较新而判它正确 |
| 范围差异 | 版本、设备、环境或适用时间不同，可以解释内容差异 | 分别保留各自条件与结论，不误标为重复或冲突 |
| 依据不足 | 适用范围或证据不足以明确分类 | 提示需要补证，不能直接确认成可合并建议 |
| 仅主题相关 | 主题有交集，但没有具体重复或冲突观点 | 保留独立，放入处理历史 |

同组只表示比较记录通过文档相互关联，不表示组内所有文档等价。比如 A 与 B、B 与 C 有重复段落，不推导 A、B、C 可以整体合并。每一对文档单独展示证据和判断。

## 后台流程

1. 默认开启，每 15 秒检查调度；一轮扫描完成后间隔 30 分钟重新检查版本。首次发现或来源变化后等待至少 60 秒稳定，再做相关文档检索。
2. 只处理 Lucyna 已登记且当前可读的 Markdown；复用第一阶段的完整性、大小、凭据筛查和来源状态检查。尚待维护的文档不会作为正常知识参与比较。外部改写不会自动导入。
3. 每轮最多检索 8 篇待扫描文档，每篇从 Stele 召回最多 8 个其他文档，按稳定文档身份、正文修订及直接来源版本去重。检索排序不当作重复概率或真实性评分。覆盖数表示完成了有界召回，不代表全库所有文档对都已穷举；未召回的相似内容可能漏检。
4. 每轮最多比较 3 对文档。辅助模型通过内嵌 `AuxiliaryAgent` 返回观点、精确引用、适用范围和具体整理方向；再使用单独请求复核证据、范围、分类和建议。无 OMP 会话、无模型文件/执行工具、无 Token 上限；沿用单次 10 分钟超时。
5. 精确摘录必须能在两侧冻结正文中定位，保存原文版本和行号。设备或版本等范围不能确定时，不允许直接给出“同范围重复/冲突”。同 Work 或共用来源会标明，不能算作独立验证。
6. 记录持久化到内部 `catalog.sqlite`，正文快照复用知识库已有的不可变修订，避免多组比较重复保存全文；列表只加载最近 200 条元数据。重复轮询不再比较同一版本；重启后已完成分析可以继续单独复核。模型凭据只在内存，后台服务重新启动后由客户端同步辅助模型配置。

知识沉淀、第一阶段维护与本批模型比较相互协调，避免同时运行同一知识服务的 agent 任务。暂停会取消在途请求，保留已有比较记录。检索失败、索引版本滞后和模型错误都有明确状态；失败的检索按尝试时间轮转，不阻塞后续文档。

## 页面和人工操作

- 按问题类型分组，筛选待处理、处理历史或全部记录；目前显示最近 200 条，完整记录仍保留在本地。
- 并排查看观点、精确摘录、范围原文、来源关联和此次比较的正文快照；可以打开当前原文核对。
- 查看具体整理步骤、需保留的内容、模型复核结果和完整处理事件。
- **确认此判断**：仅对复核通过的当前记录开放。确认前重新检查正文及直接来源版本，保存人工确认事件，原文不变。
- **保留独立 / 标记误报**：填写原因并保存。相同版本不再自动重复打扰；历史保留。
- **撤销人工判断**：把已确认或已保留独立的记录返回待处理，不修改正文。
- **重新比较**：重新分析证据不足或失败的当前版本。原文更新后，旧记录进入过期历史，重新扫描创建新比较。

模型复核用于检查判断是否得到所给文档支持，不代表进行了真实设备、代码或外部事实验证。本批发现的冲突不会直接改写第一阶段的内容，也不会把检索相似度转为知识可信度。

## 验收

- `node --test test/knowledge-governance.test.cjs`：自动发现、去重、逐项确认/撤销/误报、版本差异、同范围冲突、引用和范围约束、并发修改、来源状态、暂停/重启、批次公平性、索引滞后及来源版本失效。
- `node test/knowledge-governance-native.cjs`：真实内嵌 SDK、临时模型 HTTP 服务、真实 Stele 语义召回、私有 HTTP 操作、SQLite 持久化、重启及原文修订不变。
- `electron test/knowledge-governance-desktop.cjs`：正式 renderer 与受管 host，8 项操作验收，四主题深浅色，960/375 px 布局，人工修改后拒绝过期确认。
- 当前 MiniMax-M3.1-Flash 的隔离实测：4 篇文档形成 6 组对照，正确区分 1 组重复、2 组同范围冲突和 3 组固件差异；6 次分析加 6 次单独复核，共约 225 秒。原文修订保持不变，重复轮询没有额外模型调用。这是受控样例验收，不是任意知识库上的准确率保证。

升级不会自动重启正在工作的生产知识服务。旧服务通过能力检查给出提示；待现有任务结束后启动新版服务生效。
