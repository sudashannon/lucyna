# AuxiliaryAgent

状态为部分接入。AuxiliaryAgent 已用于 Work 多会话摘要、提示词补全、本机 Work 资料元数据推荐和 Work 内跨会话流程提醒，也支撑自动命名、知识提炼与知识维护。跨服务统一调度、交互优先级和用量治理仍待实现。它不取代原生 OMP 的主会话工具循环。

## 已接入的 Work 请求

- **Work 对话汇总**：将同一 Work 的用户和 assistant 文本归纳到固定栏目，并校验摘要条目的对话引用。
- **继续工作摘要**：将固定栏目摘要整理为当前 OMP session 的可编辑草稿，目前不选择单独主线。
- **提示建议与资料推荐**：支持本机及远端 Work 对话提示补全；本机 Work 文件和已保存 Work 资料只向模型提供筛选后的元数据，选中后才读取快照。远端资产、全局知识库及跨 Work 资料推荐待接入。
- **流程提醒**：支持 Work 内跨 session 的交接、`SESSION.md` 更新、重复阻塞和成果复用建议，并要求提供可核对出处。

## 后续请求

- **主线增量归组与状态合并**：根据来源修订维护独立主线、决定和结果记录。
- **通用复核说明**：针对给定来源检查建议的一致性并说明不确定处。现有功能仅在各自来源范围内校验输出。

摘要、提示与提醒请求没有工具，不获得修改文件、执行命令或发布知识的能力。实际文件和知识操作继续经过受限宿主。

## 后续统一调度方向

未来可在 Work 对话交互期间优先处理草稿提示，会话收敛后整理摘要，再调度不急于交互的知识沉淀。相同 Work、session、来源版本和提示模板的重复请求可复用结果。模型请求失败时保留输入状态与错误分类，后台请求不静默挤占用户正在使用的模型服务。

当前各服务有自己的请求节流、缓存或串行队列，尚无覆盖摘要、提示、提醒和知识维护的统一调度器，也没有统一交互优先级和用量治理。

## 当前基础与限制

`src/auxiliary-agent.cjs` 显式连接用户选择的 Chat Completions 或 Responses 服务，包含请求超时和凭据错误整理。设置由主进程管理。Work 摘要、输入提示、流程提醒和知识操作使用各自的受限请求；跨服务并发调度、统一优先级和用量治理尚未建立。
