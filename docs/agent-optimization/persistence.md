# Work 状态与事件持久化

Work 助手的摘要和流程提醒需要跨 session 保存，同时能够核对来源修订并恢复未完成请求。草稿提示和资料推荐则按当前输入短暂生成，不作为持久化偏好或工作记录。本模块说明这些数据的本地归属与生命周期。

## 身份与位置

本机 Work 状态按执行主机配置的发行版、用户和经主进程核实的 Work 根路径区分。SSH Work 使用 hostId 和远端根路径。session 来源用 journal 路径身份与其 Work 关联；显示标题不参与身份计算。

首批 Work 摘要状态保存在 Lucyna userData 下，每个 Work 一个 JSON 文件，写入通过临时文件替换并按 Work 串行。摘要服务持久化规范化后的有限对话片段、固定栏目摘要、sourceRevision、summaryRevision 和历史覆盖范围。流程提醒另存于独立的按 Work 身份划分的 JSON 文件，保存提醒文案、确切出处、状态、稳定提醒身份、来源指纹和文档版本。WSL 原始 Work、OMP journal、Stele 文档仍由各自系统管理。

## 记录内容

- **Work 助手摘要文件**：有限的 session 消息片段、固定栏目摘要、sourceRevision、summaryRevision、历史覆盖范围和用量信息。
- **Work 流程提醒文件**：最多五条当前提醒及有界历史提醒，含对话或 `SESSION.md` 摘录、提醒状态、状态修订号和证据指纹。提醒生命周期与去重数据按 Work 身份持久化。
- **暂不持久化的提示**：输入补全候选、资料建议、当前提示反馈计数和草稿插入结果。用户 OMP 草稿沿用既有草稿存储。
- **后续范围**：主线 ID、独立的决定和结果记录、结构化资料引用和用户可管理的 Work 偏好。

摘要状态为引用核对保留裁剪后的用户和 assistant 对话文本，不复制完整 journal 或知识库。流程提醒只保留其所需的有限出处，不保存完整对话或 Work 文档。删除会话时，摘要来源和由会话派生的流程提醒一并清理。草稿提示缓存和反馈计数目前不跨进程保留。

## 恢复和更新

已提交的摘要关联 sourceRevision 和 summaryRevision。来源变化时，旧摘要保留并标为过期；新结果只在输入修订未变化且引用校验通过后发布。

流程提醒按 Work 身份持久化生命周期和去重状态。用户操作用状态版本作并发保护；只有写盘成功后才更新内存状态。对话来源或 `SESSION.md` 变化时旧提醒会标为过期，重新分析会基于新来源生成或更新提醒。来源相同且语义相同时，提醒身份稳定，忽略状态不会因新增无关消息或引用窗口变化而重置。

进程重启后，摘要服务会把遗留的 `summarizing` 或 `collecting` 状态复位为 `idle`，并保留上次摘要与来源修订。重启不会自动重放未完成的摘要请求；用户手动更新，或新的对话事件触发后续处理。流程提醒服务读取已保存的提醒和状态；若存在当前摘要且来源版本未分析，会安排一次分析。完整 Work 删除与 host 移除的数据生命周期仍待扩展。

偏好和提醒状态保存在本机 Work 身份范围内。跨设备同步与迁移须依赖后续明确设计，不复用未经协调的路径键。
