# 原生 OMP 与子代理

状态为已有能力的协作增强。Lucyna 继续使用原生 OMP 完成主 session、子代理、工具循环、技能和模型交互。本机及已打开 SSH session 的对话事件已接到 Work 摘要，并在对应 Work 页面显示固定栏目摘要。子代理任务、工具结果与执行产物尚未映射到独立 Work 主线。

## 当前基础

`SessionManager` 管理原生 session 进程和消息。客户端支持多个 session 并行、独立草稿、交互提问、停止、历史恢复及消息队列。原生子代理任务可以订阅进度、查看详细记录和单独取消。历史时间轴负责长对话中的阅读和跳转。

## 改进方案

- 将 session 的 Work 身份、主线和成果位置关联到 Work 状态。标题仅用于显示。
- 子代理任务保留父 session 和父工具调用关系，识别子代理完成的工作属于哪条主线。
- 任务卡片补充与 Work 进展有关的结果摘要和相关资产入口。
- 进度事件与定时状态校准并用。超时或断线时以未知/待核对状态保留，待原生快照恢复。
- 按需读取详细 session、子代理记录及后台输出，概要状态轻量更新。

## 事件归属

会话事件关联 clientSessionId、原生会话 ID 和 Work 身份。远程事件还带 hostId。读取、停止和重连均继续通过各自会话适配器验证目标身份。

OMP 工具结果是执行记录。LLM 返回的结论作为 agent 陈述保存，与真实工具执行结果及用户确认分开。子代理不能因与父任务相关而越过原有工具授权。

## 实施顺序

先将已运行 session 与子代理摘要接入 Work 主线，然后扩展到已登记历史 session，再加入跨 session 结果归组与 Work 助手的快速定位。
