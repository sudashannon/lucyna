# Work 状态与多会话汇总

状态为首批已接入。Work 详情默认展示助手面板，远端 Work 页面也显示助手。摘要服务生成带原文引用的固定栏目概览，并支持从整体摘要整理继续工作草稿。

## 目标行为

目标是为一个 Work 汇总当前目标和约束、正在处理的主线、已经做出的决定、阶段性结果、阻塞、未决问题及下一步。用户打开 Work 时先看到简明概览，后续再按主线查看跨 session 的讨论和产物。选择一条主线后生成适合开启新 session 的继续工作摘要仍是后续能力。

一个 Work 可以并行处理多件事。后续汇总应将 session 放入主线，保留暂时无法归类的对话，并标出主线之间的依赖与冲突。当前实现将材料汇总到固定栏目，不创建独立主线，也不提供按主线筛选。

## 处理流程

1. 收集已打开且 journal 身份可用的本机或 SSH 会话消息，并按 Work 身份区分来源。
2. 用户触发本机历史补齐时，读取最多 12 条近期可见历史；远端历史批量补齐尚未接入。
3. 首次汇总、每 24 小时或累计 20 次成功增量后，按消息时间顺序从空摘要遍历全部保留消息，分批重建固定栏目摘要；常规更新只分析新增或正文/角色已变的消息。每个 Work 持久化消息键与正文哈希，标题和时间等元数据变化只更新摘要修订号，不触发模型请求。
4. 摘要使用带稳定条目 ID 的补丁。每轮必须逐项核对既有概况和条目，明确保留、用同一 ID 更新，或基于本轮证据关闭、合并、替代。未覆盖、编号冲突、文字完全相同的重复条目、缺少变更来源或用较早证据回退较新状态的结果不会保存；最多使用一次现有格式纠正请求，仍不合格时保留上一版摘要和检查点。消息被修改或删除时，任何引用它的整条结论都会先失效，再由当前证据重建。缺少旧证据时，按模型提出的有限查询或失效结论文本检索保留消息，最多补入 4 条 / 12,000 字，并且只接受有正向匹配的结果；最多再向模型发送一轮补充证据。没有相关来源时不会拿无关消息填充上下文。
5. 校验摘要引用确实出自本次发送的原始消息，保留来源修订与覆盖范围。界面统计本轮请求中实际发送的唯一消息数，包含按需补充的旧证据。摘要和流程提醒中的对话出处显示为精简链接，点击后定位到时间轴的原消息；不在摘要里重复展开原文。`SESSION.md` 的出处仍可按需展开核对。
6. 用户可把整体摘要整理为当前 session 的继续工作草稿；不会按独立主线筛选，也不会自动发送。

整体校正按最多 64 条消息 / 48,000 字分批运行。每个成功批次保存已访问消息哈希、进度和从空摘要构建的私有结果；所有当前保留消息都成功处理后，才一次性发布校正后的摘要。失败、取消或来源在运行中变化时，不推进对应批次的检查点。状态核对协议升级后，已有摘要会在下一次处理时进行一次完整重建，期间继续展示上一版结果。增量批次最多发送 16 条变化消息 / 24,000 字。实际发送消息由统一的 host `inventory` 提供完整保留记录，不受面向普通流程提示的证据条数上限影响。

摘要使用独立的后台请求期限（单次最多 10 分钟），不沿用会话命名和连接测试的短超时，也不设置固定输出 Token 上限。生成中仍可取消，来源变化后旧结果不发布。摘要校验保留严格的原文引用要求；截断、JSON 格式错误、引用不匹配和经过清洗的模型连接错误分别显示，不再统一归因为设置问题。记录最近尝试时间与成功摘要时间，失败不会伪造成功时间。

引用由程序把本次发送的消息拆为带 `evidenceId` 的原文片段，模型只选择片段编号，程序还原消息身份、角色与原话，再执行原有来源校验。编号只在当前请求内有效，未知编号或夹带改写引用、角色、消息身份的结果会拒绝保存；不使用模糊匹配为模型补造来源。现有摘要首次启用消息检查点时进行一次完整基线校正。失败会保留旧摘要和检查点；相同消息与模型配置不会因状态轮询自动重试，手动刷新、来源变化或配置变化才会触发重试。

模型返回的 JSON 语法错误、既有条目核对不完整、条目编号无效，或在所有引用通过核验后合并栏目仍超过 12 条时，本批最多再请求一次格式纠正。纠正请求复用相同证据，并把被拒绝的候选作为不可信输入；不会由 host 拼接 JSON、猜测编号或放宽引用检查。既有条目的稳定 ID 会按请求映射为 `g1`、`p1` 等短编号，纠正和增量补丁只接受该请求中同栏出现的编号。关闭条目必须写明 resolved、cancelled、merged 或 superseded 原因，并引用本轮实际证据；合并或替代还须指向一个仍保留的短编号。进展按里程碑整理，当前目标、决策、未决事项和下一步体现当前有效状态。旧摘要在整体校正成功前继续展示；失败诊断只记录错误类别、字符数、结束原因和可用的解析位置，不保存模型原文。纠正次数在补充旧证据轮次间共享，模型调用数与用量统计也包含纠正请求；单次调用失败或缺少用量时标记用量未知。截断响应不做语法纠正。增量变更既有状态必须引用新增或修改消息；来源时间可比较时，还禁止更早证据覆盖较新状态。时间缺失或相同的消息无法仅凭时间判断先后，模型必须保留不确定性。程序不通过关键词或文本相似度猜测事项关联，语义归并仍由模型提出。

## 状态归属

状态属于本地有效 Work 身份。session 绑定到该 Work 后，摘要引用原生 session ID、journal 路径及消息定位。SSH session 同时绑定 hostId。相同路径在其他发行版、用户或 host 下不自动合并。

当前首批摘要只纳入 user 与 assistant 的可读文本，并按消息角色展示引用。明确区分用户确认、agent 建议、工具返回和推导结论，以及跟踪 Work 文件变化，属于后续状态模型。

## 实施切片

- **第一切片，已接入**。本机与远端 Work 面板、固定栏目摘要、可跳转时间轴的对话出处、本机历史最多 12 条补齐和整体继续工作草稿均已接入。远端打开且 journal 可用的会话事件可进入摘要；远端历史批量读取和独立主线归组仍待实现。
- **第二切片**。扩大本机历史覆盖范围，接入远端历史，并从固定栏目摘要扩展到独立主线归组，区分已归类与待梳理内容。
- **第三切片**。支持用户修正主线、重命名主线、标记决定已过期及在历史修订之间查看差异。
- **后续**。将工作交接、会话产物和知识来源纳入同一条可追溯主线。

## 当前基础与限制

Work 详情已有进展字段、最新记录、未决事项和资产列表。首批摘要状态存入 Lucyna userData 下按 Work 身份区分的 JSON 文件，记录 session 消息、固定栏目摘要、来源修订和覆盖情况。session store 管理本地会话、消息、工作根和远程 host 身份。

本机 Work 可从已打开会话持续收集，并由用户触发最多 12 条可见本机历史的批量补齐。超过限制的记录、读取失败和上下文裁剪会显示覆盖说明。SSH 打开会话的事件可以进入远端 Work 摘要面板，但远端历史批量补齐待接入。当前摘要只使用对话文本与出处，不读取 Work 文件资产或知识库；用户可在独立的资产页手动把文本快照或来源信息加入当前草稿。
