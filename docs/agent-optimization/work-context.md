# Work 状态与多会话汇总

状态为首批已接入。Work 详情默认展示助手面板，远端 Work 页面也显示助手。摘要服务生成带原文引用的固定栏目概览，并支持从整体摘要整理继续工作草稿。

## 目标行为

目标是为一个 Work 汇总当前目标和约束、正在处理的主线、已经做出的决定、阶段性结果、阻塞、未决问题及下一步。用户打开 Work 时先看到简明概览，后续再按主线查看跨 session 的讨论和产物。选择一条主线后生成适合开启新 session 的继续工作摘要仍是后续能力。

一个 Work 可以并行处理多件事。后续汇总应将 session 放入主线，保留暂时无法归类的对话，并标出主线之间的依赖与冲突。当前实现将材料汇总到固定栏目，不创建独立主线，也不提供按主线筛选。

## 处理流程

1. 收集已打开且 journal 身份可用的本机或 SSH 会话消息，并按 Work 身份区分来源。
2. 用户触发本机历史补齐时，读取最多 12 条近期可见历史；远端历史批量补齐尚未接入。
3. 辅助模型将对话归纳到目标、决定、进展、未决问题和建议下一步等固定栏目。
4. 校验摘要引用确实出自提供的原始消息，保留来源修订与覆盖范围。引用卡片能展开原话，当前还不支持跳回原 session。
5. 用户可把整体摘要整理为当前 session 的继续工作草稿；不会按独立主线筛选，也不会自动发送。

摘要使用独立的后台请求期限（单次最多 10 分钟），不沿用会话命名和连接测试的短超时，也不设置固定输出 Token 上限。生成中仍可取消，来源变化后旧结果不发布。摘要校验保留严格的原文引用要求；截断、JSON 格式错误、引用不匹配和经过清洗的模型连接错误分别显示，不再统一归因为设置问题。记录最近尝试时间与成功摘要时间，失败不会伪造成功时间。

引用由程序把本次发送的消息拆为带 `evidenceId` 的原文片段，模型只选择片段编号，程序还原消息身份、角色与原话，再执行原有来源校验。编号只在当前请求内有效，未知编号或夹带改写引用、角色、消息身份的结果会拒绝保存；不使用模糊匹配为模型补造来源。旧版失败摘要在打开启用的 Work 时自动补跑一次，已使用新版引用协议的失败不会因轮询或重启反复请求模型。

## 状态归属

状态属于本地有效 Work 身份。session 绑定到该 Work 后，摘要引用原生 session ID、journal 路径及消息定位。SSH session 同时绑定 hostId。相同路径在其他发行版、用户或 host 下不自动合并。

当前首批摘要只纳入 user 与 assistant 的可读文本，并按消息角色展示引用。明确区分用户确认、agent 建议、工具返回和推导结论，以及跟踪 Work 文件变化，属于后续状态模型。

## 实施切片

- **第一切片，已接入**。本机与远端 Work 面板、固定栏目摘要、可展开的会话出处、本机历史最多 12 条补齐和整体继续工作草稿均已接入。远端打开且 journal 可用的会话事件可进入摘要；远端历史批量读取、原 session 跳转和独立主线归组仍待实现。
- **第二切片**。扩大本机历史覆盖范围，接入远端历史，并从固定栏目摘要扩展到独立主线归组，区分已归类与待梳理内容。
- **第三切片**。支持用户修正主线、重命名主线、标记决定已过期及在历史修订之间查看差异。
- **后续**。将工作交接、会话产物和知识来源纳入同一条可追溯主线。

## 当前基础与限制

Work 详情已有进展字段、最新记录、未决事项和资产列表。首批摘要状态存入 Lucyna userData 下按 Work 身份区分的 JSON 文件，记录 session 消息、固定栏目摘要、来源修订和覆盖情况。session store 管理本地会话、消息、工作根和远程 host 身份。

本机 Work 可从已打开会话持续收集，并由用户触发最多 12 条可见本机历史的批量补齐。超过限制的记录、读取失败和上下文裁剪会显示覆盖说明。SSH 打开会话的事件可以进入远端 Work 摘要面板，但远端历史批量补齐待接入。当前摘要只使用对话文本与出处，不读取 Work 文件资产或知识库；用户可在独立的资产页手动把文本快照或来源信息加入当前草稿。
