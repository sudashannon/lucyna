# 本地代码审查

本模块优先覆盖 Lucyna 中的本轮改动和当前未提交代码。审查由用户手动发起，结果保留为独立记录，可以定位差异、忽略问题、将证据加入当前会话的修复草稿。

## 第一批实现

- 本轮入口使用已保存的 turn changes，按 Work、原生 journal 身份和稳定的 `user-<timestamp>` / `skill-<timestamp>` 关联。该差异可能包含同一时间窗口内其他操作的改动。
- 工作区入口针对当前选中的本机 WSL 成员仓库，可以选择全部未提交、已暂存或未暂存（含新增文件）。同路径在 index 和工作树中的改动分别保留。
- 后端保存自包含的差异快照，审查过程不重新读取实时工作树。快照属于审查记录，独立于会话改动记录的保留策略。
- 现有辅助模型作为首个引擎，使用独立、无工具调用。它不会修改代码、执行测试或发布远端评论。当前实现尚未集成 `ai-review` Python 包，也没有自动调用 OMP 子代理。
- 结果记录模型与引擎版本、用量（提供方返回时）、覆盖不足的原因及结构化问题。原始模型输出和凭据不会写入记录。

## 数据与任务

`CodeReviewSource` 区分 `turn` 和 `workspace`；`ReviewSnapshot` 保存成员、路径、范围、patch 和警告，以内容摘要标识版本；`CodeReviewRun` 保存任务状态和 findings。问题位置通过 snapshot file id 解析，不能把模型返回的路径当作任意文件读取入口。

入口在 Electron main 验证本地 Work 身份。快照加载器在工作区变化时拒绝混合版本。任务最多同时保有四个，模型调用串行；等待模型期间已经取得的快照保持固定。

状态依次为 queued、capturing、queued、running，最终 completed、failed 或 cancelled。停止时先中止归属本任务的请求，显示 stopping，待捕获器或模型调用结束后才确认 cancelled。重启后将未完成记录标为 interrupted，不自动花费模型调用重跑。

每条记录原子写入用户数据目录 `code-reviews/<uuid>.json`，保留最近 120 条终态记录。列表按所选来源显示最近 8 次。相同来源、内容和引擎配置的成功结果可复用；失败不缓存为成功，重新尝试会新建任务。

## 覆盖范围与结果

第一版仅审查冻结 patch，不代表全仓库检查。模型输入总 patch 上限 160 KiB，单项 64 KiB；超过范围的文件整体标记未分析，不截断后冒充完整文件。二进制、无法读取或只有属性变化的项目明确列入覆盖不足。敏感配置和已识别的凭据正文不保存、不发送模型。

模型最多返回 20 个具体问题。服务核验引用文件、严重级别、代码证据和新侧行号；不能核对的文件或代码证据使本次审查失败。行号不在新侧 hunk 内时保留文件级问题并说明原因。删除问题可采用文件级定位。JSON 不完整、模型超限和连接错误不会显示成零问题。

问题仅支持待处理和已忽略之间切换；本批尚不自动断言已修复。修复按钮生成包含版本与证据的草稿，由用户发送给 OMP。

## 后续接入点

引擎协议为 `review(config, snapshot, signal) -> {findings, usage}`，任务、快照及 UI 与引擎解耦。后续可通过独立 Python 3.11 worker 适配 `ai-review` 的本地输入、上下文读取和结果输出，继续复用本模块生命周期。

历史 turn 捕获目前只持久化有限 patch。按需读文件前须增加对应版本的文件快照及内容去重，不使用历史 diff 搭配实时文件。跨文件依赖分析和增量复审将在此基础上实现：跟踪真正读取过的上下文版本，修改后复核受影响问题，保留未重新检查的问题状态。PR/MR 评论发布、SSH 审查和自动触发不属于本批。

上游调研基于 [ai-review 199446c](https://github.com/Nikita-Filonov/ai-review/tree/199446c8a08954d1f33eeb754af4040e5f22d81f)。其现成入口面向 PR/MR，需要本地适配；通用命令工具不能直接视为只读隔离机制。
