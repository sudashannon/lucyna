# Work Runner

状态为已有 WSL 后台任务能力的协作增强。Work Runner 继续负责客户端退出后持久执行的原生 OMP goal、受限文件任务、隔离命令和自动实验。Work 助手把这些执行纳入同一 Work 进展。

## 当前基础

Work Runner 在独立 WSL 用户服务运行，保存 run、事件和 OMP session journal。Work 工具具有受限 allowlist，命令在无网络与用户主目录的 bwrap 环境内运行。执行可暂停、回答问题、恢复、采纳候选和查看历史状态。

## 改进方案

- 把每个 Run 绑定到 Work 主线并生成可见结果、改动、验证状态和未决事项。
- 从 OMP 后台执行中的关键进度获取可持续状态，使 Work 助手区分客户端 session 与独立 Run。
- 为 Run 提供可导入上下文的明确资料清单，将被选材料以固定版本关联到任务。
- 服务恢复后，将 interrupted 状态、原生 journal 和可恢复步骤纳入摘要，供用户检查并选择继续。
- 在现有命令沙箱中逐步支持项目必要的构建环境。工具链由宿主配置和检查，防止准备任务假设用户目录中的任意工具可读。

## Run 与 Work 状态

Run 是执行记录，Work 助手的概览和决策是协作状态。Run 的完成只有在宿主结果返回后才记录为完成。文件变化和真实命令输出可以作为证据，模型总结与宿主验证结果保持不同类型。

自动进化仍使用当前隔离 Work 副本和候选采纳流程。Work 助手可以显示实验结果及其与当前主线的关系，实验不再作为默认的 Work 自动化入口。
