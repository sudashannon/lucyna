# 内部知识库自动维护（第一阶段）

跨文档重复与冲突的发现、建议及人工判断见 [第二阶段第一批](knowledge-governance.md)；本页描述沿已知来源关系的修订维护。

检查规则产生的“待核实”队列可按需生成 [Agent 处理建议](knowledge-review-advice.md)，结合问题类型、当前原文和相关资料提出具体处理方向。

入口：**知识库 → 知识维护 → 自动维护**。默认开启；每 15 秒唤醒调度，每 5 分钟巡检已登记文档，发现变化后等待 60 秒再处理。沉淀、维护与重复检查共用先进先出队列，每次轮转处理 1 条记录或 1 个长文分段，避免某一类任务持续抢占。首次检查建立来源版本基线，不代表现有内容已经验证。

维护使用设置中的辅助模型，通过内嵌 `AuxiliaryAgent` 发起修订和单独复核请求，不启动 OMP 会话。没有 Token 上限；单次请求超时 10 分钟。页面展示模型、上次检查、覆盖范围、处理阶段、修改对照、证据摘录、版本及检索检查结果。记录显示最近 100 条，历史修订持续保留。

## 维护对象与边界

- Lucyna 管理的 Markdown 文档及其指向已登记文档的 Markdown 引用；追踪下游引用链，包括已登记的旧路径别名。
- Work L1/L2 的来源变化通过已有 L3 沉淀记录追踪。Work 汇总交回原沉淀任务更新，维护任务随后验证新修订，保留原有贡献归属和人工冲突保护。
- 来源缺失、未登记的本地 Markdown 链接、原文投影与登记版本不一致会进入待核实，不把“失联”认定为“事实错误”。通过登记的原路径和稳定文档身份可修复迁移后的相对引用；不会按同名文件猜测。L3 证据引文里的相对链接属于原 Work 语境，不再当作知识库内失效链接。
- 单篇完整读取和版本校验上限为 2 MB；超过 120 KB 的目标按不超过 60 KB 的原文片段逐段核对，每段单独复核，全部通过后一次性保存。分段进度持久化，重启后继续。单个模型请求仍限制在 600 KB 内。长来源只选取相关片段时明确标记覆盖不完整，建议必须人工核实，不允许自动写入或确认全文仍有效。超过 2 MB、疑似凭据、原文缺失、修订不一致分别显示具体原因。外部文件修改需要先在受管版本中核对，维护不会直接导入外部改写。
- 无引用关联的文档建立基线并显示为未覆盖，不猜测其来源。暂不爬取网络链接、自动重导入外部目录、做语义去重或修改全局 skill、OMP L3 和旧 WSL Stele 数据。

底层仍由 Lucyna 保存稳定文档身份、不可变修订、乐观版本校验；内置 Stele 提供索引、检索与证据版本。维护记录保存在同一 `catalog.sqlite`，不是 Codex 定时任务。

## 从变化到结果

1. 对照来源版本与缺失状态，沿引用反向传播“待核实”。不可读资料不作为模型证据。
2. 内嵌 agent 对照当前及历史来源，返回“仍适用”“局部修订”或“待核实”。局部修订必须定位唯一原文；每处修改都带当前来源中的精确摘录。模型不能自行增加、删除引用关系或调用文件/命令工具。
3. 新请求单独复核证据、适用范围和完整性。该步骤是模型复核，不是独立实测或事实真值保证。规范、计划、设计、任务、提案及发生人工并发编辑的内容仍需确认。
4. 写入前再次检查来源和目标版本，使用持久操作 ID 保存修订。索引失败保留写入记录，重试/服务恢复不重复生成修改，不重复调用模型。
5. 重新登记索引，并检查原文一致、搜索命中目标、检索证据 hash 等于结果版本。全部通过后才显示“验证通过”；索引期间出现新版本继续保留待核实状态。

默认自动采纳已通过复核的普通局部修订；可取消该开关，让全部建议等待采纳。暂停会中止在途模型请求，已保存修订保留。恢复后继续核对，不把中断当作完成。

## 待核实内容如何使用

阅读页保留原文并提示维护状态。Lucyna MCP 的 `wiki_context` / `wiki_search` 过滤未解决文档，直接读取相关文档返回维护提示；跨文档综述、邻居和 claim 查询在存在未解决记录时暂缓，避免旧结论绕过过滤。文档摘要及该文档问答被阻止；其他文档问答限制为选定文档的当前证据，排除历史对话与图谱扩展。

这些限制作用于 Lucyna 受管访问层，不更改 Stele 原有 claim 真值，也不删除历史正文。普通浏览仍能查看原文。检测存在巡检延迟，不能保证外部变化发生的瞬间就被阻止。

## 人工操作

- **采纳此修订**：仅对复核通过的建议开放，再次核对版本后写入并验证。
- **确认原文仍适用**：对当前来源版本的显式人工确认，保留理由和事件记录，不改正文。
- **暂缓处理**：结束当前处理尝试，内容继续待核实；来源出现新版本会创建新检查。
- **重试检查**：失败记录重试；已有写入只重试发布验证。版本已变化时使用“检查变化”生成当前版本的新记录。
- **回退本次修改**：要求目标仍是本次结果版本，生成新的回退修订，绝不覆盖后续人工编辑；回退后的旧结论仍需核实。

后台处理其他文章或排队等待时，待核实记录仍可人工确认或暂缓，无需先暂停整个维护队列。确认时再次核对当前记录、原文和来源版本；过期记录不能覆盖新检查。上游待核实不妨碍你对本篇原文作出判断，但确认本篇不会同时确认上游来源。暂缓不表示内容已核实，来源或原文暂不可读时仍可操作。采纳修订、重试和回退仍等待当前后台轮次结束，页面会说明原因。

关闭客户端后，已启动的知识服务可继续运行；服务重启恢复持久队列，但模型凭据仅在内存，需客户端重新同步辅助模型配置。升级代码不会自动重启正在使用的旧知识服务；旧服务会显示明确的能力提示，应等现有任务结束后重启服务。

升级来源识别规则后，旧的大小限制或引用误报保留为历史并重新检查，不宣称已验证事实。停止服务会取消排队任务，当前提炼退出后不再开始下一个 Work。
